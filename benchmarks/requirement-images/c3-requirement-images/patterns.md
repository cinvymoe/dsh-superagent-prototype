# Reusable patterns

1. **Images over a same-origin management API.** `<img src="/orchestrator/api/...">` cannot send the `x-orchestrator-request` header, so the bytes are fetched with `fetch(url, { headers: { 'x-orchestrator-request': '1' } })`, turned into a Blob, and rendered from `URL.createObjectURL`; revoke on unmount and guard the async result against an unmounted component. This keeps the route authenticated without adding a token-in-URL image endpoint.
2. **One canonical limit constant.** The panel imports `REQUIREMENT_IMAGES` from `src/limits.ts` for its `accept`, runtime type check, byte cap and count cap, so the client and host can never disagree on the limits.
3. **Data URL doubles as thumbnail and payload.** `FileReader.readAsDataURL` output can be both the preview `src` and the create request's `data`; one read, no separate object URLs for the form, and nothing to revoke before submission.
4. **Nothing clears before the request resolves.** Keeping all form state until the create promise resolves makes host-refusal retention fall out for free; the catch only toasts the localized error.
5. **Detail de-duplication must survive a transformed Trigger.** When the server appends metadata to the requirement's original Trigger text, match the original message with a prefix of the description plus that metadata block instead of strict equality, and keep the "first match only" rule so ordinary comments (even ones quoting the description) are not hidden.
6. **Fixture mirrors the host contract.** Echoing `images` metadata on create and serving raw bytes on `GET .../images/...` (before the typed JSON route table) lets panel tests cover ordering, captions and the same-origin header without a mock-of-the-mock.
7. **Test the header, not just the DOM.** Assert `vi.mocked(fetch).mock.calls` for the image URL and its `x-orchestrator-request` header, then assert the rendered `src` is the stubbed object URL — this catches the tempting regression of putting the API URL straight into `<img src>`.
