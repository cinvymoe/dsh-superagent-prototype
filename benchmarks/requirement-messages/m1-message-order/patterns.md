# Patterns

1. **Direction lives in one comparator.** The timeline is already a merged, sorted array (`triggers + sent replies`). Reversing the conversation is `b.at.localeCompare(a.at)` plus keeping `count={events.length}`; do not reverse the DOM afterwards, or the count, keys and any future scroll anchor drift apart.
2. **Put the composer where the newest message lands.** With a descending list, placing the follow-up form before the `ul` is what makes "submit → appears right under the box" fall out without scroll code.
3. **Test document order, not pixel order.** `form.compareDocumentPosition(list) & Node.DOCUMENT_POSITION_FOLLOWING` states the contract (the box precedes the list) and survives styling changes; text offsets or DOM indices do not.
4. **A fake server must mirror the host's write semantics.** The host's `LocalIssues.comment` only bumps `updatedAt` and receives a human trigger. The old fixture appended the comment to `issue.body`, which silently re-introduced the description into the timeline (de-duplication compares the original trigger text to `issue.body`). Fix the fixture, not the component, when the panel looks wrong only in tests.
5. **Seed conversations through the fixture's own model.** `localComments`/`localReplies` keyed by issue id plus `localComment`/`localReply` builders let a panel test present a realistic thread (human + agent) without a mock of the mock; `POST .../comments` appends to the same store so a refetch shows the new message.
6. **Prove the tests bite.** Stash only the source file (`git stash push -- src/client/discuss.tsx`), run the new cases, expect red, pop. This catches a fixture that accidentally satisfies the new assertions on the old implementation.
7. **Isolated profile screenshots need the notice suppressed.** A fresh DSH web profile shows the "预览版说明" modal whose mask intercepts clicks; set `ui-settings-general.welcomeNoticeVersion` in `cordis.patch.yml` (or dismiss it) before driving the sidebar.
8. **Panel scroll containers break `full_page`.** The panel scrolls inside a nested element, so `page.screenshot(full_page=True)` still returns one viewport; raise the viewport (1440×1500 here) to capture the whole timeline for both builds.
