DSH Superagent · 003 / 005 / 007 · Agents 与能力

一个 Session 的工具集，是五层拼出来的

agents 设置不存工具清单，只存每个角色的插件开关。必需核心工具打底，内置插件组按角色声明，运行期能力开关打开才挂载，存储插件与 slice 固定策略最后叠加；宿主没注册的工具在运行期被滤掉，而不是写进名单。

By plugin, not by tool

为什么按插件配

一个能力通常要几个工具一起用（读写图片、抓网页、开子代理），按工具开关会漏掉配套的那几个。

  • 插件是能力组：打开就带来它声明的全部工具
  • requires 会一起关闭：打开一个能力，也打开它依赖的
  • 必需工具、内置组的角色范围、存储插件的范围都在保存时校验

Reconciliation

保存之后发生了什么

  • 运行中的 Session 在下一个 step 重装工具限制；进行中的 step 不变
  • 宿主卸载插件：名字被丢弃，不会顺带放进别的工具
  • 模型覆盖只影响此后新建的 Session，运行中的保持原模型
  • slice Ticket 固定策略的 feature_exec_* 与 guard 不受插件影响

Failure mode

最安静的坑

  • 面板把宿主没有的工具标成「宿主未提供」，保存不报错，但它永远进不了名单
  • 读取是宽松的：旧插件留下的名字会留到下一次保存才被清掉
  • subagent 没有独立配置，所以 worker 的插件改动会一起传下去
