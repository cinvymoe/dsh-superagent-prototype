每个 Agent 只看见自己那一份

同一个进程、同一个 store、同一份提示词版本——但一个 Session 实际拿到的是三样东西：它被拼好的那一段提示、它被允许用的那几个工具、它能写下去的那几处状态。这张图从 Agent 的位置看当前实现：Trigger 进来，主 Session 决定这条消息该由谁接手，然后那一个 Session 带着自己的眼睛去做。

读这张图的方式

四行就是一个 Session 的世界

每张卡的四行是 Agent 在自己位置上的全部依据：PROMPT 是它被拼好的那一段，TOOLS 是它被允许用的工具，WRITES 是它能改的状态，RETURNS 是它交回给人或路由的方式。

  • 同一份 prompts/*.md 与团队设置，拼出四份不同的文本。
  • 主 Session 能改设置、能派发；其余三个 Session 都改不了配置。
  • 跨 Session 的交接只有一处：store.sqlite。

五类 Session

谁在并行，谁只存在一会儿

  • 主 Session：一个进程一个，管所有项目；面板与来源的每条消息都落到它这里。
  • 讨论 Answerer：一个讨论一个，等消息时挂在会话上不退出。
  • 对齐 Aligner：一个需求一个 mode=align 工单，只提案。
  • 切片 Worker：确认后每片一单，受 worker 槽位限制。
  • 单题 Answerer：对某张工单追问时临时开一个，shared + answer.md，只回答一题、不改状态。
