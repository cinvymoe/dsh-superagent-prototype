DSH Superagent · Current Architecture

本地讨论，Router 决策，slice 执行

Discuss 面板提交需求 → Aligner 出提案 → 人确认 → Engine 按 slice 派 Ticket → Worker 在 feature-exec 的 execute flow 中实现并开 PR。
Engine 是唯一状态写入者；Router、Aligner、Worker 之间不直接对话。

Orchestration

Router · 主 Session

常驻的研判与路由 Agent，不拥有代码。

  • 读 candidate 卡，决定 accept / attach / stop / ignore
  • 本地需求用 mode='align' 接单，不直接开 worker
  • 把 Worker 的回报、提问转成对外的回复
  • 不拆 slice、不写实现计划、不调 feature-exec

Requirement alignment

Aligner · align Ticket

每个需求一个 Aligner Session，产物是提案，不是代码。

  • 读需求、仓库设计文档与相关代码
  • 调 orchestrator_align 写回 summary + slices + acceptance
  • 一个 slice = 一个 Worker 的工单，带无环 dependsOn
  • 提案不自动开工；人在 Discuss 确认后才成 Ticket
  • 没有 feature_exec_* 工具

Execution

Worker · work Ticket

每个 slice 一个持久 Session，真正改代码、开 PR。

  • assignment 携带 alignment issue/slice 与验收标准
  • 先 feature_exec_start({flow:'execute'})，再走 e1–e5
  • run 未启动时 write / edit 被 guard 拒绝
  • 依赖未结束的 slice 由 Later() 延后，不占 slot
  • 不重新讨论需求、不改已冻结的计划

State & transport

Engine · 唯一写入者

所有角色都通过 Engine 的领域命令交互。

  • Intake / Eval / Ticket / Assignment / Effects / Outbox
  • acceptPlan：确认后按 slice 原子建 Ticket
  • Ticket.plan 存 issue/slice/acceptance
  • Ticket.dependsOn 是派发顺序的唯一依据
  • SQLite 持久化；重启后 trigger / ticket / effect 可恢复

角色矩阵

角色载体负责不负责 / 硬边界
人 Discuss 面板 提交需求、审阅对齐提案、确认或打回、中途提问 不直接编辑 slice；确认动作是唯一的派发许可
Router 主 Session · orchestrator 研判 candidate、以 mode=align 接单、对外沟通、管理 Ticket 不写代码、不拆 slice、不直接调用 feature-exec；shell/job 等待上限 5 秒
Aligner align Ticket · 每需求一个 Session 读仓库与需求，产出 summary + slices + acceptance + dependsOn 不实现、不开 PR；提案必须由人确认
Worker work Ticket · 每 slice 一个 Session 启动 execute run，实现、测试、self-review、开 PR 不重新讨论需求、不改计划、不合并 PR；execute run 前不能改文件
feature-exec run execute flow · e1–e5 状态机 执行接收 → 派发 → 评审 → PR → 沉淀 不是独立 Agent；不替代 Worker 的代码工作
