DSH Superagent · 006 Deployment

一个进程，一个状态目录，两个外部账号

整个系统跑在一个 DeepSeek Harness profile 里：面板只监听 127.0.0.1，SQLite 是唯一状态，每个 Ticket 一个目录；对外只有 agent 的 GitHub 账号和可选的 Feishu bot。升级前要备份的，就是那个状态目录。

Where state lives

一个目录就是整个系统

配置分两处：插件配置只放状态目录与机器上限，其余全在面板里。

  • stateDir：数据库、锁、worker-bin shim、git 配置、工单目录
  • 升级前备份；schema 只增不减，新版本升过的库老版本打不开
  • 账号、仓库链、Policy、Execution 都在面板，不入配置文件

Isolation

权限边界在哪里

  • 两个 preset 都是 danger-full-access，以操作者身份运行
  • CLI wrapper 决定用哪个账号，但它不是安全边界
  • 要隔离就用只放 agent 凭据的独立操作系统账号
  • 面板只答 127.0.0.1，不对外暴露

Make a merge effective

升级是四步，不是一步

  • prepare：fetch + fast-forward + install + build，失败自动回退
  • activate：备份数据库 → 重启 → 不健康则回滚到旧提交
  • 宿主 profile 由它的 supervisor 重启（如 systemctl restart），脚本不碰
