DSH Superagent · 005 Panel · discussion routing delta

讨论成为一条可选的路：Router 决定先谈，人决定何时交给对齐

本地需求不再只有「直接对齐」一条路。Router 可以在候选卡上选 mode=discuss：为这条需求开一场只读讨论，不建工单、不占 worker 槽。Answerer 逐条回答；需要人拍板时，它可以用 discussion_ask 把 1–3 个问题放成一张卡，人答完作为一条讨论消息回来。结论落在右栏结果面板上；人点一次「交给对齐」，才建这个需求唯一的 align 工单，结论作为 routing note 交给 Aligner。三处 coral 与 ①②③ 就是这次改动。

Before → after

多了一条路，而不是换了一条路

  • 之前：本地需求只有一种结局——mode=align，直接进对齐，需求写得含糊就直接体现在 slices 里
  • 现在：Router 可以选 mode=discuss，为这条需求开一场讨论；不建 Ticket、不占 worker 槽，Decision 记 kind=discuss
  • 讨论仍然不是授权：它永远不产生工单；只有人点「交给对齐」，才有那个唯一的 align 工单

影响 · 流程

谈清楚再拆，少一轮打回

  • 讨论可以挂在既有需求上（Router 为它开），也可以先于需求存在（人新建）
  • 对齐工单的 routing note 直接引用结论，Aligner 据此提案，不重新讨论已定的事
  • 回答的等待跟随会话输出：2 分钟没有新事件才算卡住，30 分钟总上限——不再按 120 秒总预算误杀
  • 需要人拍板时，Answerer 用 discussion_ask 放一张卡：1–3 问、可给选项；人答完，答复作为一条讨论消息回来，只记这一次

影响 · 架构

三处小接口，而不是新子系统

  • DecisionKind 多一种 discuss：Eval 的 accept 认它，但不建 Mandate / Ticket
  • Effects 多一类 discussion：事务内入队、提交后建讨论并 seed Answerer，失败可重试
  • Engine 多一个入口 acceptAlignment：幂等 ticket id；面板与 http 各多一个按钮、一条路由
  • LocalDiscussion.asks 多一张卡，加 discussion_ask 工具与一条 reply 路由：仍只写面板记录，不碰 Engine
