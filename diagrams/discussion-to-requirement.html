DSH Superagent · 005 Panel · discussion → requirement

一段对话，变成一个可以授权的记录

讨论只是对话：每条消息由 Answerer 直接回答，永远不产生工单。人点一次 Send to issue，对话的文本才被搬进需求记录——标题取第一行，正文取全文，图片跟着走，来源双向链接。空的地方就是空的，不猜。

Why separate

讨论从不产生授权

  • 讨论的消息是普通 Trigger，存在 Thread 上，永不进 Eval
  • Answerer 是只读 Session：没有 orchestrator_align，也没有工单
  • 授权只从 Eval 的 accept 出现，需求提交后才走那条路

The handoff

人做的那一步

  • Send to issue 是面板动作，不是 Agent 的判断
  • 预填的文本仍可编辑，提交时一起带上图片与讨论 id
  • 一个讨论最多一个需求，之后按钮变成 Open requirement

No invention

空字段就留空

  • 没贴图 → 0 张；直接创建 → 没有来源讨论
  • 标题只从第一行生成，不会“总结”出一句
  • 缺的信息变成对齐阶段的一个问题，而不是猜一个值
