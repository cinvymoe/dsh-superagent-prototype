DSH Superagent · 007 Architecture · Dependency rules

依赖只朝一个方向流，core 不知道外面有谁

胶水层 src/app 向下依赖 Sources、Session 工具、管理接口和 core，core 谁也不依赖；Sources 看不见胶水层，面板只看得到类型和少数纯函数。箭头指向被依赖的一方，扇入最多的节点就是你改一处会波及最广的地方。

The rule

三条硬边界

  • src/core 不 import 外部，也不做 I/O；它只拿端口
  • src/sources 不 import src/app，只拿 SourceContext
  • 面板只 import 类型 + agent-model、admission、limits、setup、navigation、错误码与原因码

Why it matters

改一处会波及多广

  • core 的扇入是 3：胶水层、Sources、工具与接口都靠它
  • 要加一个领域命令，先改 core，再加胶水层，最后才是 Source
  • 反过来改 Source 不会碰 core 的规则，这是能并行开发的前提

One writer

状态只有一个写者

  • Trigger / Thread / Decision / Ticket / Assignment 只有 Engine 写
  • 读位置由各自 Source 通过 SourceContext 写
  • 设置、提示、effect、收据、health 各有唯一写者
