DSH Superagent · 002 Authorization · paired traces

同样的规则，为什么一个接单一个忽略

两条 Trigger 落在同一条 Thread 上，按同一顺序被判了同一套规则。差别只出现在第一关：名单内的人是显式请求，名单外的人只能得到推断档；而推断档在 observe 模式下只记录，不接单。

What actually differs

只有强度不同

两条消息命中了同一条规则，做的也是同一件事；区别在「这份请求算多强」，以及推断档能不能变成工单。

  • 切换 auto 后，B 会被接单，A 不变
  • 把 B 加进允许名单，B 就变成显式，off 模式下也成立
  • 把规则删掉后两者都不再命中，A 也只能记 ignore

Reading the cells

SKIPPED 与 NOT REACHED 不是一回事

  • NOT REACHED：前面的判定已经定了结果，这一关没有再判
  • SKIPPED：这一关适用，但流程主动绕过（如上下文订阅不查准入表）
  • 合起来写会让人以为「没查」和「查了没用」是同一件事

Same thread

两人都拿到上下文

  • 两条 Trigger 都会扇出到 Thread 上已订阅的 Ticket，作为 Input
  • 扇出不改任何 Mandate：上下文不是授权
  • 所以「B 被忽略」不等于「B 的话没人看见」
