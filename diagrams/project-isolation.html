DSH Superagent · 项目隔离审计 · global vs project scope

两个圈：进程里只有一份的东西，和一个项目自己的东西

现在能按项目分开的，只有「这个项目在哪个仓库、哪个目录、用哪条 prepare、禁哪些命令」以及它自己的需求、讨论与工单。Engine/SQLite、Router 主会话、设置与提示词、并发槽位仍然是进程内单例，所有项目共享——所以「一个项目一套配置」只做到了执行面。

Already per project

执行面已隔离

  • 仓库链（intake / code / bot / CLI）每项目一条，project.chain 决定工单在哪个仓库执行
  • worktreeRoot 与 prepare 项目可覆盖；额外 blockedCommands 只作用于本项目 Session
  • 需求、讨论、工单都带 project，面板按当前项目过滤

Still global

配置面还是单例

  • SettingsSchema 只有 paused / sources / policy / eval / executor / agents 六个全局块
  • Router 是一个主会话（runtime.master-id），所有项目共用上下文
  • 并发 maxWorkers 3 与 answerer 2 槽是全局池；暂停也是全局

Plan B

三步把圈收小

  • ① 工单存 projectId：不再从 trigger 推导，GitHub/Feishu 工单也有归属
  • ② 设置分层：projects[<id>] 覆盖 agents / eval / executor，读取统一走 settingsFor(project)
  • ③ 运行面：每项目一个 Router 会话与配额，Answerer 槽按项目切分
