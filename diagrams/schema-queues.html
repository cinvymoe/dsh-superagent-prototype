DSH Superagent · 007 Architecture · Persistence (2/2)

队列与收据：幂等键、due 排序、永不删除

第二组表不存聚合体，只存“还要做什么”和“已经说过什么”：effect 是可重试的待办，outbox 是每条消息的收据，disposition 是审计，kv 收下其余一切。

effect

待办一直留在库里

决策先写库，事后动作（launch、投递、回复、转问）在事务提交之后才执行。

  • 失败只增加 attempts 与 error，并把 due 往后推
  • 只有同一种工作连续失败三次，才成为系统问题
  • generation 让同一 key 的旧任务失效

outbox

先记收据，再发消息

  • pending = ticketId + channel.thread：同一会话内按序发出
  • 只有 pending 与 sent/dropped：丢掉的消息保留时间与原因
  • Source 关掉时消息等待，会话消失时才 drop

disposition · kv

审计与其余一切

  • disposition：每条 Trigger 去了哪里——被过滤、进了哪个 Eval、被哪个 Ticket 收到、谁交回过
  • kv：设置版本、提示版本、读位置、会话提示历史
  • 两者都不删，所以升级与排查时能回看
