## 需求原文

> Worktree root execution retry
>
> 支持 worker 在指定目录创建 worktree。项目可配置 worktree 根目录；未配置保持现状；目录不可用明确失败；更新文档测试。重试运行，验证 feature-exec dispatch 修复。

对齐时记录的原始需求（Discuss issue body）：

> 目前 worker 的 worktree 由 executor.prepare 中的命令决定，实际路径写死在命令里，无法按项目或按执行环境配置。
>
> 希望做到：
> - 可以在项目或执行器配置中指定 worktree 根目录；worker 在该目录下为 Ticket 创建 worktree。
> - 没有配置时保持现状，不影响已有部署。
> - 本地 Discuss 项目可以使用自己配置的 worktree 目录。
> - 目录不存在或不可写时给出清楚的错误，Ticket 失败而不是静默落到错误路径。
> - 更新相关文档与测试。

## 冻结的对齐决定（C1 相关）

1. 执行器级入口沿用现有 Execution 设置 `executor.directory`（Ticket directory root），不新增重复的执行器字段；新增项目级可选字段 `LocalProject.worktreeRoot`。
2. 目录解析优先级：项目 `worktreeRoot` > `executor.directory`（非空）> `<stateDir>/work`。
3. worktree 的 git 检出仍由现有 `executor.prepare` 负责；本次只决定 prepare 的工作目录和 `$DSH_SUPERAGENT_DIR`，不改为宿主自动 clone/fetch/worktree。
4. 显式配置的根目录（项目 `worktreeRoot` 或非空 `executor.directory`）在启动前严格校验：存在、是目录、可写。失败时 Ticket 明确失败，不创建根目录、不回退默认路径、不自动重试。默认 `<stateDir>/work` 保持现状（缺失时创建）。
5. 项目创建时只校验 `worktreeRoot` 是绝对路径；**省略、空字符串和纯空白视为未配置**；存在性与写权限留到工单启动时检查。
6. 已接受工单的 `execution.directory` 落库后不随设置变化；修改根目录只影响之后接受的工单。
7. 只有本地 Discuss 项目有该字段；GitHub/Feishu 工单不受影响。

范围外：Discuss 表单/HTTP 面板（C2，ticket `1478bf96058ac87a5dcf08731cb9147b`）；产品文档（C3，ticket `10cf3eb1cf2bd47e97ffc17239529bc4`）；宿主自动 git worktree、项目编辑/删除、旧工单目录迁移。

## 基线核对（本次 retry 的增量）

在 worktree 初始基线 `5556291`（其 C1 代码与 deployment main 的 `2e79202` 一致）上逐条核对冻结验收标准，C1 的核心实现（`resolvedExecutionRoot`、`ticketExecution` 的 `worktreeRoot` 落库、`verifyWorktreeRoot` 写探测、`prepareDirectory` 选定根目录、失败不重试、对应 10 个 worktree-root 用例）已由 `2e79202` 合入基线，相关测试通过。交付分支已 rebase 到 deployment `main` @ `310ae2e`（C2/C3 已合入），最终验证在 `310ae2e + 3 文件改动` 上完成。

发现一处与本次冻结标准不一致：`LocalProjectInput.worktreeRoot` 的纯空白值（如 `'   '`）在 `src/app/local.ts` 中被 trim 成空串后仍走 `isAbsolute` 校验并抛 `projectWorktreeRoot`；旧测试也把该行为固化为“空白值报错”。本次 retry 的标准 5 要求纯空白等价于未配置，因此 C1 需要这一个小改动与其测试同步。

- 旧行为（基线）：`createProject({ worktreeRoot: '   ' })` → `UserError('projectWorktreeRoot')`。
- 目标行为：与 `undefined` / `''` 一致，记录中不落 `worktreeRoot` 字段；相对路径仍抛 `UserError('projectWorktreeRoot')`。

## 验收标准（冻结版）

- `pnpm typecheck` 与相关 vitest 通过；未配置 `worktreeRoot` 的现有用例和部署行为不变。
- 项目 `worktreeRoot=/tmp/root` 时，本地工单 `execution.directory` 为 `/tmp/root/<工单短名>`；prepare 的 cwd 为 `/tmp/root`；prepare 环境中 `DSH_SUPERAGENT_DIR` 指向该工单目录，`DSH_SUPERAGENT_GITHUB_REPOSITORY` 仍为项目仓库。
- 项目未配置 `worktreeRoot` 时，本地工单仍用 `executor.directory`（非空时）或 `<stateDir>/work`；GitHub/Feishu 工单目录不因项目字段改变。
- 显式根目录不存在、是普通文件或不可写时，不启动 worker Session；最新 Assignment 报 `failed`，summary 含该绝对路径及失败原因；该路径没有被创建，默认根下也没有该工单目录。
- 这类失败不被自动重试；修正根目录后，retry 或该工单线程上的人消息能重新准备并启动。
- 已接受工单的 `execution.directory` 不因之后修改根目录设置而改变。
- `createProject` 对相对路径给出明确错误；省略、空字符串和纯空白等价于未配置。
