# C1 · 能力插件：按角色手动启用标准模式的「零副作用」插件（运行期挂载）

- Alignment issue: 本会话聊天对齐（`m00003` 提问 → `m00547` 拍板），无 Discuss 面板 id
- Slice: `C1`（无前置依赖；C2 依赖 C1）
- Flow: execute / scope: shared / product: shared / policy: A1
- Dispatch cwd: 待建分支（`/data/project/dsh-superagent/.agents/worktrees/dsh-8f6cec15-d90d` 为当前勘察工作区）

## 需求原文

> 当前 Agent 的配置 我想实现的效果是 当前默认其他插件不会注入到这个工具的两个角色中。我是想通过手动配置，自动的加入标准模式中使用的插件。请先讨论如何实现

> 都要  选了某个插件就自动带出它的依赖插件是先只做 ask-user / present / web-fetch / fork-subagent 这批"零副作用"的  能

对齐后的四点约束：

1. **两个角色都要**：`main`（主 Session，router preset）与 `aligner`/`executor`（worker preset）都能在面板上手动启用这些插件。
2. **默认不注入**：未手动启用时，工具表与 system prompt 里都不应出现这些能力的任何痕迹（不是「注册了再掩码」）。
3. **选中即带依赖**：启用一个插件时，它声明的依赖插件自动一起启用（面板联动 + 保存兜底）。
4. **第一批只做零副作用四项**：`ask-user`、`present`、`web-fetch`、`fork-subagent`；`goal` / `plan-mode` / `workflow` / `ralph` / `schedule` / `plugin-manager` / `codex` / `claude-code` 留第二批。
5. 接受版本耦合：peer 依赖跟随 DSH 已装版本。

## 对齐结论（需求级，冻结）

- **这些能力就是标准模式里的现成插件包**，不为 superagent 另写工具实现：`@deepseek-ai/dsh-tool-ask-user`、`dsh-tool-present`、`dsh-tool-web`、`dsh-tool-subagent`（fork provider）。
- **默认不挂载**：两个角色 preset（`dsh-superagent-router` / `dsh-superagent-worker`，见 `cordis.patch.yml`）保持现状不动；四项都不在 preset 行里出现，`DEFAULT_ENABLED_PLUGINS` 也不默认开启。
- **手动启用 = 运行期挂载**：面板保存后，由 `dsh-superagent` 在对应 Agent 的 scope 里用 `ctx.plugin(module, config)` 现场挂载该插件模块；取消启用即 dispose。
  - 插件挂进 Agent **自己**的 scope ⇒ 工具注册在 own 层，`ctx.tools.restrict()` 的 allow list 管不到它（`dsh-tools` 的 `view()` 把 own 层无条件并入），因此**不需要**把能力工具塞进 `roleTools`。
  - 未启用 = 插件不存在 = 无工具、无 prompt 段。这正好满足「默认不注入」；这也是**不能**用「preset 预挂 + allow list 掩码」的原因——`dsh-system-prompt` 的段注册不受 restriction 影响，`tool:goal` / `tool:workflow` / `tool:ralph` 这类静态段会无条件进 prompt（本批四项虽都不带静态段，但机制必须按将来能接第二批的方式设计）。
- **依赖声明**：`AgentPlugin` 增加 `requires?: string[]`，保存与面板都做传递闭包。第一批四项之间确实没有交叉依赖（`requires` 均为空），字段与闭包逻辑先落地并用测试替身验证；第二批（`ralph` → `workflow`、`goal` → `command-goal` 等）再真正吃到。
- **自定义插件仍受 `FORBIDDEN_ADDED_TOOLS` 约束**：本次放开的是内置能力目录项，不是自定义插件声明任意工具的口子（`ask_user_question` / `present` / `create_goal` 等仍在自定义插件的禁令里）。
- **不改上游**：挂载只用 `ctx.plugin(module, config)`，模块按 profile `baseUrl` 解析（与 Loader 同一解析与 Config 校验路径），不改 `dsh-agent-preset-registry` 与任何 `@deepseek-ai` 包，也不新增 `cordis-plugin-loader` 依赖。

## 现状与问题

1. **能力组只有 allow list，没有注册层**：`src/app/agent-tools.ts` 的 `BUILTIN_PLUGINS`（`image` / `web` / `skills` / `todo` / `subagents` / `billion-context`）都是「工具已由 preset 注册，插件只决定放不放行」。`roleTools()` 返回的 allow list 里出现未注册名字会让 `tools.restrict()` 抛 `names unknown global tool`，所以现有插件目录**永远无法**表达「这个工具根本不存在」。
2. **标准模式独有能力不在两个角色 preset 里**：`ask_user_question`、`present`、`web_fetch`（worker 的 `tool-web` 是 `fetch:false`）、`subagent_fork` 在 `dsh-superagent-router` / `dsh-superagent-worker` 行清单中都没有对应插件行。面板勾选也无济于事——工具不存在。
3. **面板与保存只知道「工具名」**：`AgentPlugin` 只有 `{id,name,description?,tools,roles?}`，没有「用哪个插件包、什么配置、依赖谁」的概念；`agentCatalog()` 的 `missingTools` 按宿主张量计算，运行期挂载的工具不在宿主工具表里，会被误标成「宿主未提供」。
4. **没有卸载路径**：`SessionBinding`（`src/app/sessions.ts:48`）只有 `disposers`/`skills`/`tools`，`release()` 不知道要停掉挂载树。

## 验收标准（冻结版）

1. **默认零注入**：不勾选任何新能力时，`main`/`aligner`/`executor` 三个角色的工具表、`roleTools()` 输出、system prompt 段与改动前逐项相同（现有 `tests/agent-config.spec.ts`、`tests/runtime.spec.ts` 不改断言即通过）。
2. **手动启用即生效**：在面板启用 `ask-user` 并保存后，已存在的主 Session 在其**下一 step** 就能看到 `ask_user_question`；服务不重启、Session 不重建。
3. **取消即卸载**：取消启用并保存后，下一 step 工具表里该工具消失；Session 不报错、继续可用；重复开关幂等。
4. **故障隔离**：某个能力包在本机不可解析（或挂载失败）时，只记一条 `warn`，该能力在该 Session 上失效，其余能力与 Session 正常；面板把该项标成「宿主未提供」。
5. **allow list 干净**：`roleTools()` 永不包含 `providedBy:'mount'` 的工具；三处 `tools.restrict()`（`mainTools` / `workOnly` / `limitSubagent`）都不因这些名字抛 `unknown global tool`。
6. **依赖闭包**：保存一个带 `requires` 的启用项时，服务端补齐其传递依赖；面板在勾选时同时勾上依赖项。用测试替身定义（`requires` 非空的假能力）验证，真实目录项的第一批 `requires` 均为空。
7. **面板可读**：四个能力在三个角色的插件区都出现，中英文案齐全，标明「运行期挂载」与工具明细；未启用时显示 `agentPluginDisabled`，不显示假的「宿主未提供」。
8. **文档登记**：`docs/007-architecture.md` 的 agents 段、模块表、测试表登记新模块与新测试；`docs/005-panel.md` 的智能体页段落补插件依赖联动说明。
9. `pnpm check`（lint + typecheck + build + 全量测试）通过。

## 接口契约

### 目录（`src/app/agent-tools.ts`）

`BuiltinPlugin.providedBy` 扩为 `'preset' | 'host' | 'mount'`，`mount` 项额外带：

```ts
interface MountedPluginSpec {
  module: string                                   // 例如 '@deepseek-ai/dsh-tool-ask-user'
  config: (role: AgentRole) => Readonly<Record<string, unknown>>
}
interface BuiltinPlugin extends AgentPlugin {
  providedBy: 'preset' | 'host' | 'mount'
  mount?: MountedPluginSpec
}
```


第一批四项（`id` 取名避开已用的 `web`/`subagents`）：

| id | name | roles | tools | module | config |
| --- | --- | --- | --- | --- | --- |
| `ask-user` | Ask user | 全部 | `ask_user_question` | `@deepseek-ai/dsh-tool-ask-user` | main `{mode:'legacy'}`；aligner/executor `{mode:'timed', timeout:120}` |
| `present` | Present | 全部 | `present` | `@deepseek-ai/dsh-tool-present` | `{}` |
| `web-fetch` | Web fetch | 全部 | `web_fetch` | `@deepseek-ai/dsh-tool-web` | `{search:false, fetch:true}` |
| `fork-subagent` | Fork subagent | 全部 | `subagent_fork` | `@deepseek-ai/dsh-tool-subagent` | `{provider:'fork', toolName:'subagent_fork', agentPreset:<该角色的 preset id>}` |

- `web-fetch` 挂第二个 `dsh-tool-web` 实例只注册 `web_fetch`，不与 worker preset 里 `tool-web {fetch:false}` 注册的 `web_search` 撞名。
- `fork-subagent` 的 `agentPreset` 取该角色自己的 preset，子 Agent 继承同一编排层。
- `requires`：第一批均为 `[]`（`AgentPluginSchema.requires?: string[]`，默认空）。

### `roleTools` / `agentCatalog`

- `roleTools()` 只并入 `providedBy !== 'mount'` 的插件工具；`mount` 项对 allow list 不可见。
- `agentCatalog()` 对 `providedBy:'mount'` 跳过与 `availableTools` 的比对：`missingTools: []`、`provided: true`；真正的可用性由挂载结果决定，失败时经 `Sessions` 暴露诊断（见下）。

### 挂载器（新文件 `src/app/capabilities.ts`）

```ts
interface CapabilityInstance { dispose(): unknown }
type CapabilityLoader = (module: string, config: Readonly<Record<string, unknown>>) => Promise<CapabilityInstance>

class Capabilities {
  constructor(ctx: Context, options?: { load?: CapabilityLoader; warn?: (message: string) => void })
  sync(role: AgentRole, agents: AgentsConfig): void   // 串行 reconcile；幂等，可在每次工具刷新时调用
  settle(): Promise<void>                             // 等排队中的 reconcile 完成（测试/关闭用）
  stop(): void                                        // 卸载全部，幂等
}
```

- 默认 loader：`ctx.get('loader').internal.import(module, ctx.baseUrl)`，无该服务时退到 `createRequire(profile/package.json)` 动态 import；取 `namespace.default ?? namespace`，再 `ctx.plugin(plugin, config)`。
- `ctx.plugin` 走 Cordis 的 `resolveConfig` 标准 schema 校验（与 Loader 行配置同一路径），并把工具注册进 Agent 自己的 scope → own 层，`restrict` 不可见。
- 以 plugin id 记录已挂载实例；`sync` 先把最新目标集写入 `wanted`（供迟到的 load 判断是否已被停用），再把 reconcile 排到 `queue`；失败按 id 记入 `failed`，同一 id 只 warn 一次。
- `stop()` 清空 `wanted` 并逐个 dispose；load 在 stop 之后完成时立即 dispose，不留在 scope 里。
- 失败告警走 `ctx.logger.warn`（或注入的 warn）：`dsh-superagent could not mount the <id> capability (<module>): ...`。

### 生效链路（`src/app/sessions.ts`）

- `decorate()`：创建 binding 后 `binding.capabilities = new Capabilities(agent.ctx)`。
- `mainTools` 的 refresh 闭包与 `workOnly` 的 `allow` 闭包开头调用 `binding.capabilities?.sync(role, agents)`（保存后 `agentsChanged()` 触发同一个 refresh，自然对运行中的 Session 生效）。
- `limitSubagent()`：worker 的子 Agent 与 worker 同角色，同样创建 `Capabilities`；它跑 standard preset，能力工具同样进 own 层。
- `release()`：`binding.skills?.dispose()` 之后、摘 restrict 的 disposers 之前 `binding.capabilities?.stop()`。

### 保存与面板

- `Settings` 的 `agents.parse`：先 `closeAgentsPlugins(AgentsConfigSchema.parse(value))` 做三角色传递闭包，再 `validateAgentPlugins`；未知/不适用依赖报 `agentsPluginRequires`。
- 面板 `toggle(role,id,on,catalog)`：开启时按目录 `requires` 传递闭包一起打开；关闭只关该项，不级联关闭依赖它的插件。

## 避坑清单

- **不要把这些工具塞进 `roleTools`**：own 层工具不可被 `restrict` 命名，塞进去会让未挂载的 Session 抛 `unknown global tool`。
- **不要把插件挂到 Agent 的子 scope**：链只向上，子 scope 的工具 Agent 看不见。
- **不要用 preset 预挂 + allow list 掩码替代**：`dsh-system-prompt` 的段不受 restriction 影响；第二批的 static 段插件会漏进 prompt。
- **DSH 工具包导出的是对象插件**（`{ name, apply, inject, Config }`，`default` 为空），不是函数；loader 必须同时接受函数与带 `apply` 的对象，否则四个能力全部挂不上。
- **模块解析必须走 profile baseUrl**：bundle 自己的 node_modules 只有 27 个 DSH 包，四个能力包都不在；优先用 `ctx.get('loader').internal.import`，退路 `createRequire(profile/package.json)`。
- **不要用 `EntryTree`**：它需要新增 `@deepseek-ai/cordis-plugin-loader` 依赖，且落盘/审计/`!!js` 插值都用不上；`ctx.plugin` 的 Config 校验与工具注册语义等价。
- **`sync` 必须在每次工具刷新时调用一次**：`agentsChanged()` 只触发 refresh，不单独遍历 binding；漏接会让保存后运行中的 Session 不生效。
- **`stop()` 要幂等**：`release` 与「能力全关」两条路径都会停，需防重复 dispose。
- **别动 `FORBIDDEN_ADDED_TOOLS`**：本次放开的是内置目录项；自定义插件仍禁 `ask_user_question`/`present`/`create_goal` 等。
- **fork 子代理的 `agentPreset` 要显式给**：不给则继承调用方 preset，跨角色时容易拿到不适用的工具面。
- **`dsh-tool-subagent` 的 prompt 段按可见性静音**，但只在工具名与配置的 `toolName` 一致时生效——默认 `subagent` 会被 worker preset 占名，必须显式 `toolName:'subagent_fork'`。
