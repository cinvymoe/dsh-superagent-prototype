## 接口契约（冻结）

`GET deployment/prepare` → `PrepareStatus`：

```ts
{
  checkout: CheckoutView,     // C1 事实 + committedAt（ISO） + remotes [{ name, repository|null }]
  chain: string | null,       // 匹配到的链路 id
  repository: string | null,  // 匹配到的链 code repository（小写 owner/name）
  available: boolean,         // reasons 为空
  reasons: PrepareReason[],   // checkout.reasons 在前，其后 noChain、empty
  running: boolean            // 当前有一次 prepare 在执行
}
```

`POST deployment/prepare`（无 body）→ `{ merged: boolean; head: string | null; log: string }`：

- 成功或本来就最新 → 200；`merged = 合入前后 HEAD 不同`。
- 不可用（含 setup 未完成、没有匹配链路、空仓库、脏树等）→ 400 `code: prepareUnavailable`，`values.reasons` 为逗号分隔的原因码。
- 已有一次在执行 → 400 `code: prepareBusy`。
- 脚本拒绝/失败 → 400 `code: prepareFailed`，`values.message` 为脚本输出尾部（≤ 4000 字符），`values.log` 为日志绝对路径。

原因码顺序：`notGit, noRepository, detached, notMain, dirty`（C1 不变；`checkoutReasons` 与 `CHECKOUT_REASONS` 保持原义），其后 `noChain`（没有任何链路的 code repository 出现在检出的 remote 里）、`empty`（没有 HEAD 提交）。

路由**不得**调用 restart/exit、不发送 SIGTERM/SIGINT、不写 Settings、不触碰 Ticket。

### T1 acceptance

- **事实**：`readCheckout` 额外读 `git log -1 --format=%cI`（`log` 加入 `CHECKOUT_GIT` 白名单）与全部 remote（`git config --get-regexp '^remote\..*\.url$'`，仍属 `config` 子命令）；`CheckoutView` 增加 `committedAt: string | null`、`remotes: { name: string; repository: string | null }[]`（只列 GitHub 可解析的仓库与非 GitHub 的 `null`，按 remote 名排序；读失败留空而不是抛错）。读取仍只用 `rev-parse`/`symbolic-ref`/`config`/`status`/`log`，不触网、不改树。
- **匹配与判断**（`src/app/prepare.ts`）：`Prepare` 类（类前 JSDoc）构造入参含检出目录、`chains: () => { id; repository }[]`（惰性，setup 未完成时为空）、日志目录、可注入的脚本执行器。`status()` 先取 `CheckoutView`，把每个链的 code repository（小写）与 `remotes[].repository` 比对，取第一条匹配；`available = reasons.length === 0`；`reasons = [...checkout.reasons, ...(chain ? [] : ['noChain']), ...(head ? [] : ['empty'])]`。
- **动作**：`Prepare.merge()` 在第一次 `await` 之前占用单飞标记；不可用抛 `UserError('prepareUnavailable')`，已在执行抛 `UserError('prepareBusy')`；否则以检出目录为 cwd 运行 `scripts/dsh-superagent prepare --repository <repository>`，stdout/stderr 落 `<stateDir>/prepare/prepare-<stamp>-<pid>.log`（0600，保留最近 10 份）并保留尾部；退出码非 0（含 spawn 失败）抛 `UserError('prepareFailed', { message, log })`，成功返回 `{ merged, head, log }`（合入前后 HEAD 不同即为 merged）。子进程环境清掉 `GIT_LOCATION` 指向的变量并设 `GIT_TERMINAL_PROMPT=0`/`GIT_ASKPASS=''`，保留用户 git 配置以便 fetch 认证；绝不 `process.kill`/`process.exit`/restart。
- **路由**：`GET deployment/prepare` 返回 `PrepareStatus`；`POST deployment/prepare` 返回 `{ merged, head, log }`。`Api` 增加两条类型契约；`HttpHost` 只暴露 `Pick<Prepare, 'status' | 'merge'>`；`Runtime` 用 `packageRoot()`、`packagePath('scripts','dsh-superagent')`、`machine.stateDir` 与 `() => chains`（来自 `setup.configured() ? setup.deployment.chains : {}`）构造并挂载。
- **面板**：Deployment 页新增「运行中的检出」区块（`Section`），行含路径、分支、`<code>` 短 HEAD（7 位，title 全量）+ `When(committedAt)`、工作树（干净/有改动）、匹配链仓库；`available=false` 时列出 `checkoutReason.*` 文案并禁用按钮；`setup.accounts === null` 时显示等待文案；可用时 `ConfirmButton` 文案「拉取并构建」，确认文案含仓库与「不重启、重启后生效」；成功后 `notify` 成功文案并 `reload`，`restartRequired` 时显示「重启后生效」徽标；失败时区块内持久展示「拉取并构建失败」+ 脚本文本 + 日志路径（来自 `ApiError.details.user.values`），不导航；`useAction`/本地 busy 防重复点击。
- **文案**：`locales.ts` 新增键 zh/en 成对（占位符一致）；`USER_ERRORS` 新增 `prepareUnavailable`、`prepareBusy`、`prepareFailed` 及两语言 `userError.*`。

## 避坑清单

1. **docs.spec 逐文件核对**：`src` 下每个 `.ts` 必须在 007 Modules 表、`tests` 下每个 `*.spec.ts(x)` 必须在 Tests 表，且表里不能有不存在的路径；`src/app/prepare.ts`、`tests/prepare.spec.ts` 都要登记。
2. **class-docs.spec**：`Prepare` 类前必须是 JSDoc（`/** … */` 紧邻 `class`）。
3. **面板 fake server 穷尽 `Api`**：`tests/fixtures/panel-server.ts` 的 `ROUTES` 缺一条新路由就 typecheck 失败；`usePanelServer` 断言 `server.misuse` 为空，`query`/`body` 声明必须与 `Api` 完全一致（本 slice 的 GET 无 query、POST 无 body）。
4. **单飞要在第一个 await 前占位**：`merge()` 里先判断并置位再 `await status()`，否则并发双请求都通过。
5. **日志不能写进检出**：`prepare` 在合入前跑 `git status --porcelain`，检出里多一个未被忽略的文件会被判脏树而拒绝。日志写 `<stateDir>/prepare/`，权限 0600，保留最近 10 份。
6. **匹配链仓库必须看全部 remote**：本部署 `origin` 是上游、部署仓库在 `deployment` remote；只比 origin 永远 `noChain`。`git config --get-regexp '^remote\..*\.url$'` 的输出是 `remote.<name>.url <url>` 行。
7. **只读命令白名单**：新增 `log`（`-1 --format=%cI`）与 `config --get-regexp` 都在本地且只读；C1 的只读性测试会遍历 `CHECKOUT_GIT`，不要在读取路径引入 `fetch`/`remote`（`git remote` 命令）之类。
8. **C1 的 `toEqual` 断言**：`tests/checkout.spec.ts` 有多处对 `CheckoutView` 的完整 `toEqual`，新增字段后要同步更新（扩展契约，不是改语义）；`reasons`/`CHECKOUT_REASONS` 语义不变。
9. **不发送信号**：路由与 `Prepare` 只 spawn 脚本；不要为了「生效」调用 restart、`process.kill`、`process.exit` 或 `ctx.root.dispose`。测试会 spy `process.kill` 并断言 POST 后 `GET state` 仍应答。
10. **失败信息**：把 stdout+stderr 合并后的尾部裁剪到 ≤4000 字符作为 `message`；`prepare` 的多行拒绝信息（例如脏树清单）要保留可读前缀；日志路径用绝对路径返回。
11. **面板轮询**：区块用 `usePoll(() => call('GET deployment/prepare'), [call])`；动作完成后 `reload()` 让新的 HEAD 与 `restartRequired` 反映出来；`settle()` 要求 fake server 的 pending 归零，fake 应答必须立即 resolve。
12. **样式复用**：用既有 `dt-*` 类（`KeyValues`、`Hint`、`dt-error`、`dt-mono`、`dt-badge` 等），不要新增全局样式或改 `client.css` 之外的结构；`styles.spec` 可能核对类名来源（先看它的断言）。
13. **两处渲染**：`DeploymentPage` 同时用于设置页和 Plugin Manager；新区块保持共用，不要绑定 `accounts` 分支。
14. **不回归既有面板用例**：`tests/panel-deployment.spec.tsx` 现有 4 条用例的文案断言必须仍通过（新文案不要与「仓库克隆」「工单 worktree 目录」等已移除字段混淆）。
15. **中文文案要落到 `TEXT`**：`locales.spec` 校验 zh/en 占位符一致、每个 `USER_ERRORS` 都有 `userError.*` 两语言条目。
