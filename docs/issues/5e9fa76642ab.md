## 对齐结论（需求级，冻结）

执行策略独立于 Policy 版本：Policy 版本只覆盖规则、接受模式与 Source Policy；执行模式属于 Executor 指令，不参与 `policyVersion`。执行策略自带版本 `execution-v1`，Ticket 派发时固定 `plan.execution = { mode, version }`，后续默认值或策略版本变化不影响已建 Ticket。

- 新需求未显式选择时默认 `native`；需求记录缺字段也按 `native` 派发。
- 需求详情在确认对齐前可切换模式并立即持久化；需求已有派发 Ticket 后只读。
- 本次全部 slice：C1 核心模型与派发固定（PR #18）；**C2 需求侧存储、修改接口与派发传递（本 slice）**；C3 执行策略 seam；C4 面板开关；C5 文档。

## 现状与问题

- `LocalIssue` 没有执行模式字段，本地需求无从记录“走原生还是 feature-exec”。
- 现状执行路径由“Ticket 有没有 plan”硬编码：`src/app/sessions.ts` 的 `workOnly`/`decorate` 与 `src/app/prompts.ts` 的 `composeExecute` 都按 plan 存在即 feature-exec，执行策略与 plan 绑死。
- `Runtime.dispatchPlan` 调 `Engine.acceptPlan` 时没有传执行策略；C1 已让 `acceptPlan` 接受并固定 `plan.execution`（缺省 native），本 slice 负责把需求侧的模式传到这个 seam。

## 验收标准（冻结版）

1. 新建需求未指定时为 native；调用新接口改为 feature-exec 后，读取需求返回 feature-exec。
2. 需求已有派发 Ticket 后调用新接口被拒绝，需求记录保持不变。
3. 确认对齐后生成的每个 Ticket 的 `plan.execution` 与需求当前模式一致；存量无字段需求按 native 派发。
4. `pnpm vitest run tests/local.spec.ts tests/local-align.spec.ts` 与 `pnpm typecheck` 通过。
