## 需求原文

> 需求列表 讨论 支持 对齐历史 记录。比如我回复 需要修改什么地方 后生成新的对齐记录。
> 2 可以  对齐的工单进行提问。并接收提问反馈。  看看如何  完善。如果判断是 提问能否 使用 fork session 提问 然后 反馈到讨论列表

## 对齐结论（需求级，冻结）

本需求分两部分：**对齐历史**与**对已对齐工单提问并把回答反馈到讨论列表**。C3 已交付第二部分的问答会话端口（`Questions.ask`：从 `worker-<ticketId>` 最新已完成回合 fork 一次性只读会话，只允许 `read`/`read_image`/`glob`/`grep`，答完归档；失败返回带原因的 `questionResult`）；**C4 只交付“需求侧提问记录 + HTTP API + 后台队列”**，把 C3 的端口接到需求记录上：

- 需求的提问记录挂在需求记录 `LocalIssue.questions[]`（`asked` → `answered` / `failed`），**不进 Engine**：提问不产生 Trigger/Eval/Ticket/Assignment，不唤醒、不 resume、不改动工单。
- `POST local/issues/:id/questions` 立即返回 `asked`（回答在后台队列里生成），前端不必等待一次 fork 问答。
- 后台队列消费 C3 端口：成功记录 `answered` + 非空 `answer`；失败记录 `failed` + `error`，并可用 `retry` 重新排队（复用同一条记录 id，不新增记录）。
- 服务重启后把仍为 `asked` 的提问重新排队；本次中断不影响记录（中断时不写 `failed`）。
- 只允许对**该需求派发过的 slice 工单**提问，且该工单必须已启动 worker 会话（有 `assignment.startedAt`）；否则拒绝并给出明确错误码。
- 面板入口、等待/失败/重试展示与 Markdown 渲染属 C5，本切片不做面板。

## 现状与问题

- `LocalIssue` 只有对齐与执行模式字段，没有任何提问记录；`LocalIssues` 没有提问方法，`/orchestrator/api` 没有提问路由，`src/app/api.ts` 也没有对应契约。
- C3 的 `Questions` 端口已经可用（`ask(ticket, question, { signal?, timeoutMs? })` → `{ ok: true, answer } | { ok: false, reason, message }`），但没有任何上层调用它：人都无法就某个已派发工单提问，也没有地方保存回答。
- 没有后台队列与重启重排：若在 HTTP 请求里同步等待一次 fork 问答（最长 120s），面板请求会挂住，进程重启还会丢掉进行中的提问。
- 没有任何错误码覆盖“工单不属于该需求”“工单从未启动会话”“只有失败的问题能重试”“提问数超上限”这些拒绝路径。

### T1 acceptance（实现契约）

- `LocalQuestions.ask(issueId, ticketId, text)`：未知需求返回 `undefined`；空文本抛 `questionText`；未知工单抛 `unknownTicket`；`ticket.plan?.issueId !== issueId` 抛 `questionTicket`；`ticket.assignments` 无 `startedAt` 抛 `questionNoSession`；已有 `questions.length >= QUESTION_LIMIT(20)` 抛 `questionLimit`（values `{ max }`）；通过则在同一次同步调用里写回带 `asked` 记录的 `issue`、返回 `{ issue, question }` 并在后台启动回答。
- 后台回答：重读工单（已不存在 → `failed`，error 说明）；调用问答端口（带 `host.lifetime` 的 `signal`）；成功且 answer 非空 → `answered` + `answer` + `answeredAt`；端口失败或空回答 → `failed` + `error`（端口 message，空回答给固定说明）。写回前重读需求记录，只改这条 `asked` 记录，保留其它字段与问题；关闭/中断（`lifetime` aborted 或 `stopping`）时**不写记录**，保持 `asked` 供下次启动重排。
- `LocalQuestions.retry(issueId, questionId)`：未知需求/提问返回 `undefined`；非 `failed` 抛 `questionNotFailed`；工单已不存在抛 `unknownTicket`；通过则把同一条记录改回 `asked`（清 `answer`/`error`/`answeredAt`，`askedAt` 更新为本次时间）并在后台重排。
- `LocalQuestions.resume()`：遍历 `local.list()`，把每条 `asked` 记录排队；同一 `issueId:questionId` 已在队列中不重复排队。
- `LocalQuestions.idle()`：等待当前与后续排队的回答全部落定（测试与 shutdown 用）；`stop()` 置 `stopping` 并 `await idle()`。
- HTTP：`POST local/issues/:id/questions` body `{ ticket: string, text: string }`（trim、1..4000 字符）→ 200 `{ issue, question }`；`POST local/issues/:id/questions/:questionId/retry` → 200 `{ issue, question }`；未知需求/提问 404；`questionTicket`/`questionNoSession`/`questionNotFailed`/`questionLimit` 为 400 且 body 带 `code`。
- 不进 Engine：提问与回答路径只写 `local-issue:` 记录，不调用 `Engine` 写命令；`store.tickets`/`store.triggers`/`store.decisions` 只读。

## 避坑清单

知识库检索（关键词：`LocalIssue`、`questions`、`Questions.ask`、`USER_ERRORS`、`userError.`、`local/issues/*/questions`、`runtime.initialize`；范围：`benchmarks/`、`docs/issues/`、`docs/007-architecture.md`、C3 交付记录）：

1. **新错误码必须同时有 zh/en `userError.*` 文案**，否则 `tests/locales.spec.ts` 的“words every refusal”用例失败；错误码只加在 `src/core/errors.ts` 的 `USER_ERRORS`。
2. **不进 Engine**：不要用 `Engine` 的 input/report 路径承载提问；只写 `KV.local.issue`。测试要显式断言工单 `inputs/assignments/ended`、Trigger 数、Decision 数不变。
3. **立即返回**：HTTP 路由不得 `await` 端口；`ask()` 同步落 `asked` 后 `queueMicrotask`/`void this.answer()` 启动后台。测试用 `local.idle()` 收敛。
4. **重读后写回**：回答完成时重读需求记录再改单条记录，避免覆盖并发写入（评论/对齐）；只在原记录仍为 `asked` 时落结果，避免覆盖重试生成的新状态。
5. **中断不写 failed**：`lifetime` aborted 或 `stopping` 时直接返回，让记录保持 `asked`，否则“重启后重新排队”永远不可达；`stop()` 必须在 `store.close()` 之前完成。
6. **重启重排的测试形态**：`startRuntime(seed)` 的 seed 在 Runtime 构造前写 store；用 `KV.local.issue` 写入带 `asked` 记录的需求与对应工单，启动后 `await h.runtime.localQuestions.idle()`，断言记录不再是 `asked`（真实端口因无 worker 会话返回 `no-session`）。
7. **`view()` 透传**：所有返回需求的 HTTP 路由都在 `runtime.local.view()` 之后追加 `questions`，新路由同样返回 `view(issue)`，不要返回裸记录。
8. **`api.ts` 只导入类型**（面板会打包它），不要从 `src/app` 导入运行时代码。
9. **文档表**：新增 `src/app/local-questions.ts` 必须登记到 `docs/007-architecture.md` 的 Modules 表，`tests/docs.spec.ts` 会校验；没有新增测试文件，Tests 表只更新两行描述。
10. **类 JSDoc**：`LocalQuestions` 前必须有 JSDoc 块，`tests/class-docs.spec.ts` 会校验。
