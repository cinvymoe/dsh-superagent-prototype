## 需求原文

> 需求列表 根据处理 情况进行 筛选显示 默认显示 待处理

需求列表（Requirements 页签）当前把当前项目的全部需求按创建时间倒序铺开，已关闭与已确认的需求和待处理的需求混在一起。本 slice 给列表加一条筛选行，按处理情况分桶显示，默认只显示待处理的需求。

## 验收标准（冻结版）

- 无路由筛选时，需求列表只显示开放且对齐缺失、已提议或已打回的需求；已确认与已关闭不出现在列表中；「待处理」pill 的 aria-pressed 为 true，Section 计数等于当前显示条数。
- 筛选行按 待处理/已确认/已关闭/全部 的顺序显示且中英文正确；点击任一 pill 后以 replace 更新路由（待处理不写 filter query），列表只显示该桶的需求并按创建时间新到旧排列；「全部」显示当前项目所有需求。
- 从非默认筛选打开需求详情再返回，列表保持同一筛选；在需求列表页切换项目时保持筛选并按新项目重新取数。
- 有需求但当前筛选为空时显示新的空态文案；完全没有需求时保留原空态；详情页与新建需求页行为不变。
- pnpm typecheck、pnpm test（含更新后的 panel-discuss/panel-projects/navigation 与 locales 文案校验）和 pnpm build 通过；pnpm check 退出码为 0。
- docs/005-panel.md 的 Requirements 行写明四种筛选与默认待处理；未新增模块或测试文件，007 架构表保持不变。
- PR 描述含同一视口、同一主题、同一份种子数据的 Before/After 截图并标注基线 main 版本与被改 head：默认列表（Before 全部需求；After 仅待处理）、一个非默认筛选、以及详情返回后筛选保留。

## 任务拆解

- **C1（本 slice）**：在 `src/client/route.ts` 增加需求筛选类型与 list/detail 路由的 `filter` query（默认 `pending` 不落 query，旧 `discuss` 路由继续迁移）；`src/client/app.tsx` 把筛选传给列表与详情；`src/client/discuss.tsx` 渲染筛选行（`Pill` + `aria-pressed`）、按桶过滤并以显示条数作 Section 计数，补筛选空态且保留无需求空态，详情返回时带上同一筛选；`src/client/projects.tsx` 在需求列表切换项目时保留筛选；`src/client/locales.ts` 增加四枚 pill 与筛选空态中英文；更新 `tests/panel-discuss.spec.tsx`、`tests/panel-projects.spec.tsx`、`tests/navigation.spec.ts` 的既有用例断言（不新增测试文件）；更新 `docs/005-panel.md` 的 Requirements 行。
- **不在本次**：服务端分页/服务端筛选、需求状态机或对齐语义变化、详情页与新建需求页的内容/交互变化、其它面板页面、007 架构表改动。

## 实现方案（要点）

- **路由**：`REQUIREMENT_FILTERS = ['pending','confirmed','closed','all']` 与 `RequirementFilter` 落在 `src/client/route.ts`；需求列表与详情路由带 `query?: { filter?: RequirementFilter }`，新建/编辑项目路由不带。`parseRoute` 丢弃未知值、把默认 `pending` 规范为「无 query」，旧 `discuss` 路由（含筛选）继续映射。
- **列表**：`RequirementList({filter})` 仍只用一次 `GET local/issues?project=` 取数，客户端按互斥且覆盖全部记录的桶隐藏行：`closed` 按需求状态、`confirmed` = 开放且对齐已确认、`pending` = 开放且无对齐/已提议/已打回、`all` = 当前项目全部；不重排，保留宿主的新到旧顺序。筛选行按固定顺序渲染既有 `Pill`（`aria-pressed`），点击 `pending` 写无 query 的列表路由、其余带 `query.filter`，全部 `replace`；Section 计数 = 显示条数。
- **空态**：完全无需求保留 `discuss.empty`；有需求但当前桶为空显示新增 `discuss.emptyFilter`。
- **详情与项目切换**：行标题打开详情时携带当前筛选，详情返回按钮回到同一筛选的列表（`replace`），详情内容/取数不变；需求列表根页切换项目时保留筛选并触发新项目重新取数。
- **文案与文档**：`requirementFilter.pending/confirmed/closed/all`（待处理/已确认/已关闭/全部）与 `discuss.emptyFilter` 中英文；`docs/005-panel.md` Requirements 行写明四种筛选、默认待处理、replace 语义与两处筛选保留。未新增模块或测试文件，`docs/007-architecture.md` 未改。
