## 需求原文

> 需求列表 根据处理 情况进行 筛选显示 默认显示 待处理

需求列表（Requirements 页签）当前把当前项目的全部需求按创建时间倒序铺开，已关闭与已确认的需求和待处理的需求混在一起。本 slice 给列表加一条筛选行，按处理情况分桶显示，默认只显示待处理的需求。

## 验收标准（冻结版）

- 无路由筛选时，需求列表只显示开放且对齐缺失、已提议或已打回的需求；已确认与已关闭不出现在列表中；「待处理」pill 的 aria-pressed 为 true，Section 计数等于当前显示条数。
- 筛选行按 待处理/已确认/已关闭/全部 的顺序显示且中英文正确；点击任一 pill 后以 replace 更新路由（待处理不写 filter query），列表只显示该桶的需求并按创建时间新到旧排列；「全部」显示当前项目所有需求。
- 从非默认筛选打开需求详情再返回，列表保持同一筛选；在需求列表页切换项目时保持筛选并按新项目重新取数。
- 有需求但当前筛选为空时显示新的空态文案；完全没有需求时保留原空态；详情页与新建需求页行为不变。
- pnpm typecheck、pnpm test（含更新后的 panel-discuss/panel-projects/navigation 与 locales 文案校验）和 pnpm build 通过；pnpm check 退出码为 0。
- docs/005-panel.md 的 Requirements 行写明四种筛选与默认待处理；未新增模块或测试文件，007 架构表保持不变。
- PR 描述含同一视口、同一主题、同一份种子数据的 Before/After 截图并标注基线 main 版本与被改 head：默认列表（Before 全部需求；After 仅待处理）、一个非默认筛选、以及详情返回后筛选保留。
