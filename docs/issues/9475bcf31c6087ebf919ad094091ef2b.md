## 对齐结论（需求级，冻结）

本需求分两部分：**对齐历史**与**对已对齐工单提问并把回答反馈到讨论列表**。本次 slice `C2` 只交付第一部分的**面板展示**：在已冻结的宿主轮次契约（C1：`LocalAlignment.roundId`、`status: superseded`、`LocalIssue.alignments[]`、`alignmentRounds` / `currentAlignment` 读取器）之上：

- 需求列表行显示该需求的**对齐轮数**（没有对齐时不显示轮数）。
- 需求详情按轮展示对齐历史：**当前轮**始终展开（摘要 / 切片 / 验收标准 / 提议与决定时间），**旧轮折叠**，展开后可见该轮的摘要、切片、验收标准；折叠态仍可见该轮状态、时间与**打回原因**。
- **确认 / 打回只作用于当前轮**：按钮只在当前 `proposed` 轮出现，决定请求携带当前 `roundId`；旧轮不出现决定按钮。
- 读侧沿用 C1 的归一化：仅存 `alignment` 单槽的存量记录按一轮读取，不改存储。

## 现状与问题

- C1 已把宿主记录改为轮次历史，但面板仍只读 `issue.alignment` 单槽：详情只渲染最新一轮，看不到上一轮摘要/切片/验收与打回原因，列表行也没有轮数。
- C1 的面板改动只做到“决定携带当前 `roundId`、认识 `superseded` 标签”，轮次历史本身没有 UI；C2 需要把 `alignmentRounds` / `currentAlignment` 读侧接到列表与详情。
- 决定按钮若仍挂在单槽上，旧轮历史与当前轮无法区分，容易在历史页面上误确认新轮。
