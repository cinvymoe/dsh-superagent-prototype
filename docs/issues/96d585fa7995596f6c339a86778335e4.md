## 对齐结论（需求级，冻结）

本需求分两部分：**对齐历史**与**对已对齐工单提问并把回答反馈到讨论列表**。C3 交付问答会话端口（fork 只读问答），C4 交付需求侧提问记录、HTTP API 与后台队列；**C5 只交付面板入口与文档收口**：

- 提问入口放在需求详情「关联工单」的每一行，与既有的「打开 Session」按钮共存，不新增独立页，需求列表不带问答。
- 时间线（消息记录）同时承载问题与其回答：`asked` 显示等待、`answered` 用 Markdown 渲染回答、`failed` 显示原因并可重试（同一记录重新排队），问题文本与回答文本各出现一次并标注所属工单。
- 面板只读既有契约：`POST local/issues/:id/questions`（body `{ ticket, text }`，即所属工单 id 与问题文本）与 `POST local/issues/:id/questions/:questionId/retry`；`ticketId` 的字段名在 C4 冻结契约里是 `ticket`，C5 按该契约发请求，不改宿主路由。
- 面板不为没有 worker 会话的工单提供提问入口：宿主会以 `questionNoSession` 拒绝，同「打开 Session」按钮一样只在已启动会话的行出现。

### T1 acceptance（实现契约）

- 关联工单行：已启动 worker 会话的行在「打开 Session」旁多一个提问按钮（`discuss.ask`），点击展开内联输入框与提交按钮；提交与「打开 Session」两个动作互不影响。
- 提交：`POST local/issues/:id/questions`，body `{ ticket: <工单 id>, text: <trim 后文本> }`；成功后重读需求详情，输入框关闭，问题出现在时间线。
- 时间线事件（与既有真人消息/智能体回复同列，按 `askedAt` 参与 newest-first 排序）：
  - `asked`：问题文本 + 等待文案（`discuss.questionAsked`）。
  - `answered`：问题文本 + 回答（`MarkdownLite`，含 `answer`）。
  - `failed`：问题文本 + 原因（`error`）+ 重试按钮（`discuss.questionRetry`），点击发 `POST local/issues/:id/questions/:questionId/retry`，成功后重读详情。
  - 每个事件都带所属工单标签（`discuss.questionOf` + 工单标题，找不到标题时用工单 id）。
- 文案键中英双语齐全（`tests/locales.spec.ts` 校验占位符一致）。
- 文档：`docs/005-panel.md` Requirements 行写明提问入口、等待/回答/失败重试与所属工单；`docs/007-architecture.md` 的 `src/client/discuss.tsx` 与 `tests/panel-discuss.spec.tsx` 行同步。
- 视觉证据：同一视口（1440×900）、同一主题（默认深色/浅色以现网一致）的 before/after 截图，before 取基线 `422a21a4`（含 C4 契约但不含 C5 面板），after 取本工单 head；PR 描述标注两者版本并说明与「打开 Session」按钮共存。
