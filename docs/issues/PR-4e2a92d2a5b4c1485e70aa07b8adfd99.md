## Outcome

每个本地项目拥有自己的 GitHub 仓库链路（chain id = 项目 id）：`POST local/projects` 接收 `intakeRepository`/`codeRepository`/可选 `worktreeRoot`，只向 `settings.sources.github.config.chains` 追加一条 `id=项目 id` 的链路且已有行逐字段不变，返回的项目视图含两条仓库；`PUT local/projects/:id` 只更新该项目自己的链路与元数据，另一个项目的链路行深度相等。仓库不可读/不可推送、重名、仓库格式非法返回 400，且不留下项目记录或链路。

项目工单的 `execution.chain` 等于项目链路 id，`DSH_SUPERAGENT_GITHUB_REPOSITORY`/`DSH_SUPERAGENT_GITHUB_INTAKE_REPOSITORY` 等于该链路的 code/intake 仓库。只有 `repository` 的旧项目启动时幂等绑定到 code repository 相同的既有链路；无匹配的项目仍按原 repository 执行，且不改动链路配置。面板创建页收集两个仓库，Discuss 页头显示 `intake → code`。

## Risks and limitations

- `POST local/projects` 的请求形状从单 `repository` 改为两仓库；面板与 HTTP 测试已同步。in-process 仍可创建旧记录，已存旧记录保持可读。
- 运行期新建的项目链在其被下一次重启解析前，工单从已存配置读取该链；解析后使用 resolved deployment，两者给出相同的 chain id 与仓库。
- 无数据库迁移：项目记录原地扩展；启动绑定只写项目记录，不写 settings。
- 未启用 auto-merge，PR 由人复核合并。
