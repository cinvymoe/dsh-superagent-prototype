## 需求原文

> superagent 当前有几个执行的 Agent？需要在设置界面新增一个 Agent 的配置 页面 支持自定义当前 Agent 的工具和一些相关配置。

对齐结论（需求级，已冻结）：三类可配置角色 —— 主 Session、对齐 Agent、执行器；执行器的子代理继承执行器工具，不单独配置。C1 已交付 `agents` 设置块（数据模型、工具目录、校验、管理 API、历史 diff）；C2 已让保存的块在运行期生效（工具限制在下一步重新安装、模型覆盖只影响新 Session）。本 slice 只做面板「智能体」设置页、面板文案、路由与文档，不改设置块语义与运行期行为。

## 现状

- `SETTINGS_GROUPS` 只有 `source / eval / execution / prompts / deployment`，没有「智能体」组；`GET settings` 已返回 `blocks.agents`（value + revision）与 `agents.roles` 工具目录（C1），但没有页面消费它们。
- 面板已有 `useBlockDraft`/`SaveBar`（乐观并发草稿、会话内草稿、三方合并与冲突提示）、`ModelField`、`ConfigHistory` 与 `settingsRoute`，可直接复用。
- `roleModel`（`src/app/role-models.ts`）是角色模型继承的唯一实现：主 Session ← `eval.model`；执行器 ← `executor.model`；对齐 Agent ← 执行器覆盖，否则执行器有效模型。面板需要展示同一口径的继承值。

## 验收标准（冻结版）

1. 设置导航出现「智能体」（执行之后、提示词之前），路由刷新/返回保持；页面列出主 Session、对齐 Agent、执行器，并说明子代理继承执行器工具。
2. 执行器卡片显示当前 `running / maxWorkers`，链接可跳到「执行」组，不在此处修改并发。
3. 每类角色的模型留空时显示继承的实际值（主 ← 评估模型；对齐/执行器 ← 执行模型；对齐默认继承执行器覆盖），可设置覆盖并一键恢复继承。
4. 工具列表：必需工具固定勾选且不可改；可选工具可开关；保存 PUT `settings/agents` 的 `disabledTools` 正确；冲突保留草稿并显示冲突提示。
5. 保存栏仅在改动时出现；历史能读到 agents 保存并显示角色/模型/工具变化；zh/en 齐全。
6. `pnpm vitest run tests/panel-agents.spec.tsx tests/panel-settings.spec.tsx tests/locales.spec.ts tests/docs.spec.ts` 与 `pnpm typecheck` 通过；PR 前 `pnpm check` 全绿；PR 含 Before/After 截图。
