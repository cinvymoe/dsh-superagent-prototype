# q-e88931b6 · C1 — Clear filters on the Execution ticket list

## Requirement

> Add a clear-filters button to the ticket list
>
> On the ticket list page, when a non-default filter is active, show a small clear filters button next to the filter tabs. Clicking it returns to the default filter. Reuse existing buttons and icons.

Frozen decisions from the approved alignment discussion:

1. "A filter is active" means the selected Ticket filter is not `open`, the default applied by `src/client/app.tsx`.
2. The control lives in the existing `.dt-filters` row of `ExecutionStatus`, directly after the filter pills.
3. It is a small outline `Button` (not a `Pill`), with the existing `filter` `Icon`, labelled by a new
   `clearFilters` locale key.
4. It resets with the same navigation as the Open pill: `setLimit(20)` and `navigate({ page: 'execution' }, true)`,
   so the route has no filter query and no extra history entry.
5. No new route state and no change to `TICKET_FILTERS`.
6. The Trigger (Thread) and Eval (Decision) filter rows are out of scope.
7. `docs/005-panel.md` describes the button in its Execution row.

## 验收标准（冻结版）

1. With the default Open filter active, the Execution filter row renders no Clear filters control.
2. With Pending, Working, Waiting for a Trigger, or Ended active, a small outline Clear filters button labelled
   清除筛选 / Clear filters appears directly after the Pills and uses the existing Button and Icon primitives.
3. Clicking it returns to Open: the route has no filter, the Open Pill is active, the list requests
   `tickets?state=open&limit=20`, and the button disappears.
4. `tests/panel-execution.spec.tsx` covers the hidden, shown and reset cases; `tests/locales.spec.ts` passes with the
   new key in both languages.
5. `pnpm check` passes.
6. The PR description includes labelled Before and After captures of the Execution list with a non-default filter
   active, at the same viewport and theme, naming the baseline and changed revisions.
