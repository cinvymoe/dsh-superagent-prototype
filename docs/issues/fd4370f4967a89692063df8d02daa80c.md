## 实现方案（要点）

- **选择**：新建需求页的描述框下增加隐藏的多选 `<input type="file" accept="image/png,image/jpeg,image/webp,image/gif" multiple>` 与可见的「选择图片」按钮；`accept` 只影响文件选择器，真正的类型判断用 `file.type`。选中后异步读为 base64（`FileReader.readAsDataURL`），生成缩略图（对象 URL 或 data URL）、文件名与大小；限制提示写明 PNG/JPEG/WebP/GIF、每张 ≤5 MiB、最多 4 张。
- **客户端拒绝**：逐个检查媒体类型、大小与数量上限；任一文件不合法时不发起提交，给出本地化提示（不合法文件不加入已选列表；已有合法选择保留）。描述为空或提交中仍禁用提交。
- **提交**：`POST local/issues` 的 body 为 `{ body, project, images: [{ name, mediaType, data }] }`，描述与图片在同一次请求；成功清空描述与图片并进入需求详情。服务端拒绝时只显示本地化错误，描述与已选图片保留。
- **展示**：详情页需求原文下方按 `issue.images` 顺序渲染缩略图，文件名与字节数作为辅助信息；图片经 `fetch('/orchestrator/api/local/issues/<id>/images/<imageId>', { headers: { 'x-orchestrator-request': '1' } })` 读取字节，`URL.createObjectURL` 后赋给 `<img>`，卸载时 `revokeObjectURL`。不把图片 URL 直接写进 `<img src>`，避免浏览器请求缺少 same-origin 头而被 403。
- **列表计数**：需求列表行在切片数旁显示图片数量（有图片时），文案中英文齐全。
- **文档**：`docs/005-panel.md` 的页签说明补提交表单的图片用法与四条限制。
